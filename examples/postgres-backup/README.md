# PostgreSQL 备份示例

在 GoDesk 或独立 `ext` 中配置多个 PostgreSQL 数据源，探测数据库和 Schema，执行整库备份，并从历史归档恢复到新库或替换现有库。宿主运行时在后台执行任务，关闭插件页面后任务继续运行。

## 安装

1. 在 Linux 宿主的 `PATH` 中安装与 PostgreSQL 服务端兼容的 `psql`、`pg_dump` 和 `pg_restore`。插件还使用 `install`。
2. 在仓库根目录运行 `make examples`。将 `dist/com.godesk.postgres-backup-0.1.0.zip` 安装到 GoDesk「扩展」或 `ext` 管理页并启用。
3. GoDesk 需使用包含目录校验的 Extension Host 后端。本示例开发期间保持 `0.1.0`，可用热重载或重新打包验收。

Manifest 省略权限声明。运行插件的宿主账号仍需能够启动 PostgreSQL 客户端，并读写所选备份目录。已有旧版插件数据时，首次启动会迁移连接、对应定时任务和备份记录。旧归档继续从插件原数据目录读取。

## 数据源与备份

- 在左栏「数据源」中新建连接，也可按名称、主机或服务名搜索已有连接。可填写主机、端口、用户名和入口数据库，或选择宿主已配置的 PostgreSQL 服务名。连接验证成功后保存。中栏列出当前账号有连接权限的数据库，右栏显示所选数据库的 Schema 和备份记录。
- 密码可由 `PGPASSFILE` 提供。页面填写的密码保存在插件本地 SQLite，网页只显示是否已保存密码。编辑时留空保留原密码，也可主动清除。服务名模式使用宿主的 `PGSERVICEFILE`。
- 单击「立即备份」生成自定义格式的整库 `.dump`。Schema 用于查看数据库结构。所有归档使用各自的绝对文件路径，修改全局目录后，历史归档仍可从原路径恢复。
- 在独立 `ext` 的「管理 → 插件配置」或 GoDesk「扩展」的「配置」中填写备份目录及并行上限，插件停止时也能保存。宿主会创建缺失的目录并实际试写文件。目录无法创建或无法写入时保留上次保存的配置。留空时归档写入插件自己的数据目录。备份归档权限为 `0600`。在「备份记录」中可以手动删除文件，并保留执行记录。

## 定时任务

每条任务绑定一个数据源和一个数据库，可选择每天、每周、标准五段 cron 或 `@every`。任务可独立启停或手动运行。计划按宿主本地时区触发，宿主或插件停机错过的触发不补跑。任务注册后，支持该接口的宿主会提供下次运行时间。

默认最多并行运行两个任务。同一已配置数据源下的同名数据库同时只运行一个备份或恢复操作。发生冲突或达到并行上限时，定时触发记为「已跳过」，手动操作提示原因。

## 恢复、替换和切回

1. 在成功的备份记录中单击「恢复」，选择目标数据源、目标库名和管理数据库。管理数据库必须可以连接，并与目标库不同。目标连接需要建库权限。替换和切回还需要改名与终止相关会话的权限。
2. 恢复在临时库中执行，默认保留归档中对象的属主和授权。跨实例时可选择将对象归目标连接用户并跳过原对象授权。数据库级属性以及集群角色和表空间定义需要在目标实例另行管理。
3. 「恢复到新数据库」在恢复成功后发布为指定的新库名。「替换现有数据库」在临时库恢复成功后进入待确认状态。到「恢复记录」确认切换，输入目标库名以断开相关连接并执行改名。插件会保留改名前的旧库。
4. 需要回退时，在恢复记录中执行「切回旧库」。切回前正在使用的库也会保留，可在确认数据后手动清理。切换失败或中断可重新核对实际数据库状态。必要时由管理员处理外部改名、持续重连或权限问题。

## 验收

用相同 ZIP 在独立 `ext` 和 GoDesk 打开。配置两个测试数据源并探测数据库与 Schema。从宿主的插件配置保存一个尚不存在的多级目录，确认自动创建。再填不可用路径，确认错误提示和原配置保留。等待一条定时备份成功后，从其归档恢复到新库并查询已知数据。另准备一个已存在的测试库，确认替换前继续保持原数据，切换后查询归档中的数据，切回后查询原数据及保留库中切回前的新写入。
